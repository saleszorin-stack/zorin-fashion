# Начни отсюда

Это сайт-визитка швейной фабрики **ZORIN** (Бишкек, Кыргызстан) —
контрактное производство мужской классической одежды оптом. Next.js,
статическая сборка, без бэкенда и базы данных. Владелец репозитория,
Vercel-проекта и домена — сам заказчик, полный доступ у него.

## Быстрый старт

```
npm install     # один раз
npm run dev     # http://localhost:3000
npm run build   # проверка прод-сборки
npm run lint    # проверка стиля перед коммитом
```

## Деплой

Просто `git push` в `main` — GitHub↔Vercel подключены на автодеплой,
через несколько минут изменения уже на `zorin-fashion.com`. Ручной
`vercel --prod` не нужен в обычной работе.

## Какие инструменты есть

- **git** — коммиты, пуш, всё как обычно, аккаунт уже настроен на
  машине владельца.
- **Playwright MCP** (`.mcp.json` в корне) — браузер для визуальной
  проверки правок: открыть страницу, сделать скриншот, кликнуть,
  проверить, что ничего не съехало. Первый запуск может попросить
  `npx playwright install` — поставит браузерные бинарники.
- Никакого специального бэкенд-доступа не требуется — сайт статический,
  вся логика в TypeScript-файлах ниже.

## Где лежат факты — не выдумывать, редактировать эти файлы

- `src/lib/site.ts` — контакты, юрлицо, статистика компании
- `src/lib/products.ts` — 5 линий продукции (костюмы/пиджаки/брюки/
  жилеты/школьная форма), MOQ/сроки/цены
- `src/lib/faq.ts` — вопросы-ответы
- `src/lib/articles.ts` — статьи блога
- `src/lib/nav.ts` — меню

## Справочные материалы (не в git, см. `materials/README.md`)

Бриф заказчика и файл с ключевыми поисковыми запросами передаются
отдельно (не через репозиторий — он публичный). Если папки `materials/`
нет — взять файлы у заказчика напрямую.

## Если нужна история решений

- **`AGENT_START_HERE.md`** — подробный журнал сессий: что и почему
  делалось, что специально не трогать и почему. Длинный, но самый
  надёжный источник контекста, если что-то непонятно.
- **`PROGRESS_LOG.md`** — архитектурные решения отдельно.
- **`BLOG_BACKLOG.md`** — темы для блога и как устроена автопубликация
  (пока держится на облачном роутине разработчика, не заказчика — см.
  запись в `AGENT_START_HERE.md` про этот план).

## Главные правила (коротко)

1. **Не выдумывать факты.** Цены, сроки, объёмы, отзывы, кейсы, лого
   партнёров — только из `materials/` или уже опубликованного на
   сайте. Нет данных — оставить честный плейсхолдер, не сочинять.
2. **Не добавлять лишнего.** Задача — не повод для рефакторинга или
   новых фич сверху. Один экран — одна правка.
3. **Проверять перед тем как считать готовым.** `npm run build` и
   `npm run lint` чистые + визуально посмотреть через Playwright MCP —
   не просто «код написан».
4. **Не гнаться за красивым, если это шаблонно.** Клиент несколько раз
   отклонял дизайн как «нейронный». Рамки на карточках, три одинаковые
   колонки, курсив вперемешку с прямым текстом — сигналы того же самого.
5. **Блог — не штамповать одинаковые статьи.** Формат/длина/структура
   должны отличаться от последних 4–5 статей, иначе это читается как
   спам поисковиками (см. подробности в `BLOG_BACKLOG.md`).
