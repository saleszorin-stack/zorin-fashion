# Progress Log — Zorin Fashion

### Audit-driven редизайн дизайн-системы (2026-08-18)

**Решение:** Вместо очередной угадайки — прогнали структурированный аудит
(8 скриншотов всех страниц + 4 референса клиента, 4 независимых
агента-критика по отдельным оптикам: типографика / композиция / арт-дирекшн
/ посыл) и перевели совпавшие находки в план
(`~/.claude/plans/purrfect-dancing-harbor.md`). Реализовано: цветовые
токены на холодную серо-голубую палитру с акцентом-синим от логотипа
(`--accent: #2c5a86`, было `#a8462c` терракота); убраны рамки-карточки
(`rounded-2xl border ... p-6`) почти везде в пользу hairline-разделителей;
единый класс `.eyebrow` вместо 3 разных tracking-значений; единая шкала
заголовков (h1 внутренних страниц vs секционный h2, раньше пересекались по
размеру); в Hero убран курсив на целом предложении внутри `<h1>`, посыл
услуги поднят в заголовок; FAQ на главной ограничен 6 пунктами вместо 14
(было ~24% высоты страницы); `/o-fabrike` сокращён с 5 плейсхолдер-секций
до 2 (оставлено только реально запланированное — фото/видео и логотипы
клиентов, кейсы/отзывы/награды убраны за отсутствием данных и сроков);
`/produktsiya` карточки получили MOQ/срок между заголовком и описанием.

**Причина:** Клиент несколько сессий подряд отклонял дизайн как «нейронный
и шаблонный», в этот раз явно потребовал структурированный процесс (аудит →
согласие нескольких независимых оптик → референсы → только потом правки)
вместо очередной единоличной перекраски. Два независимых критика (по
композиции и по арт-дирекшну) независимо назвали именно карточки-с-рамками
и 5-секций-плейсхолдеров на `/o-fabrike` главными «шаблонными» сигналами —
второе было прямым следствием более ранней правки этой же сессии (см. запись
ниже), важный урок: честная заглушка тоже может выглядеть шаблонно, если
исполнена как генерик-компонент без вариации.

**НЕ МЕНЯТЬ потому что:** Цвет/типографика/анти-card-паттерн — это
согласованная система, а не одна из проб. Если снова покажется «шаблонно» —
сначала сверить, о какой версии речь (могут иметь в виду старый скриншот),
не откатывать вслепую на дотерракотовую палитру.

### Настройка GitHub-репозитория на аккаунте клиента (2026-08-17)

**Решение:** Весь код запушен в `https://github.com/saleszorin-stack/zorin-fashion`
(публичный репозиторий, аккаунт клиента `saleszorin-stack`, не
разработчика) — до этого в git был только пустой `create-next-app`, вся
реальная работа висела незакоммиченной. Доступ на запись — SSH deploy key
(`~/.ssh/zorin_deploy_key`), привязан только к этому репозиторию через
`git config core.sshCommand` (локально в `.git/config` проекта, не
глобально) — проверено дважды: `git push --dry-run` подтвердил права на
запись до реального пуша, и отдельно проверено, что глобальный
`~/.ssh/config` и другие проекты (`umai-bot`, `ai-studio`) не задеты.
`.claude/` (локальные Claude Code скиллы) намеренно не запушен — это тулинг
для разработки, не часть сайта, добавлен в `.gitignore`.

**Причина:** Пользователь хочет, чтобы сайт существовал независимо от
разработчика — код и (в будущем) Vercel-проект должны быть под контролем
клиента, а не личного аккаунта. GitHub — первый шаг, Vercel Team клиента
будет следующим (см. «Что не сделано» в `AGENT_START_HERE.md`).

**НЕ МЕНЯТЬ потому что:** Deploy key ограничен именно этим репозиторием —
не путать с личным SSH-ключом разработчика (`~/.ssh/github_ratmir`,
используется для всех остальных проектов). Не перенастраивать глобальный
`~/.ssh/config` под нужды zorin — это сломает доступ разработчика к его
собственным репозиториям.

### Зарезервированные места под материалы от клиента (2026-08-17)

**Решение:** Добавлен переиспользуемый компонент `ContentPlaceholder`
(пунктирная рамка + подпись «что появится и когда») и расставлен на сайте
под материалы, которых физически ещё нет: логотипы клиентов (`/o-fabrike` +
тонкая полоса `ClientLogos` на главной), реальные фото/видео цеха, кейсы с
цифрами, отзывы, сканы наград/сертификатов — всё на `/o-fabrike`.

**Причина:** Прямой запрос пользователя — не тратить время на выдумывание
контента, которого нет (кейсы, отзывы, реальные цифры цен), но и не
замалчивать эти разделы: должно быть видно, где именно на сайте появится
материал, когда клиент его пришлёт. Цена «от X» отдельного плейсхолдера не
получила — уже и так честно стоит «по запросу» в `products.ts`, менять
нечего до появления цифр.

**НЕ МЕНЯТЬ потому что:** Пустые плейсхолдеры на `/o-fabrike` — это
осознанная заглушка, а не недоделанная секция. Не удалять «потому что там
пусто» — при получении реальных материалов от клиента заменять конкретный
`ContentPlaceholder` на контент, а не вычищать всю секцию.

### Настоящий векторный логотип вместо текстового wordmark (2026-08-17)

**Решение:** Пользователь прислал растровый PNG логотипа (ZORIN, галстук
вместо буквы I, тёмно-синий на белом) и попросил «сделать нормальным».
Первая попытка — ручная реконструкция через fontTools (Archivo Black
глыфы + нарисованный от руки галстук) — была разумным приближением, но
затем пользователь прислал точный файл-первоисточник
(`~/Downloads/122 (1).png`). Его перетрассировали **точно** через OpenCV:
`cv2.findContours(RETR_CCOMP)` для контуров с учётом дырок (О, Р) +
`cv2.approxPolyDP` для сглаживания + один `<path fill-rule="evenodd">`.
Результат — точная копия контуров присланного файла, не приближение.

Логотип встроен как `src/components/Logo.tsx` (`fill="currentColor"`,
наследует цвет — тёмный в светлом хедере, светлый в тёмном футере),
плюс сохранён как отдельный `.svg`-файл на Desktop и в `public/logo/` —
закрывает блокер из брифа («логотип нужен в векторе»).

**Причина:** в брифе явно указано: «Растровая картинка из анкеты для
сайта не годится», нужен `.ai/.svg/.eps/.pdf`.

**НЕ МЕНЯТЬ потому что:** это не сгенерированный с нуля логотип, а точная
трассировка присланного заказчиком файла — если понадобится другой формат
(.eps/.pdf) или другая версия, трассировать заново тем же способом
(potrace/imagemagick на машине нет — использовался Python
opencv-python-headless, который уже установлен).

бордерах вместо текстур и скруглений, блок контактов и футер — сплошной

соответствовала ожиданию «современно и привлекательно», карта была признана
лишней (нет смысла показывать карту небольшого села, когда контакты и так
даны текстом).

**НЕ МЕНЯТЬ потому что:** возврат к тёмной теме или добавление карты обратно
без явного запроса пользователя повторит уже отклонённое решение. Если в
будущем понадобится карта — обсудить формат заново (например, встроить её
иначе, не как fullwidth iframe).

### Шрифт Archivo не подошёл (2026-08-15)

**Решение:** Изначально для заголовков планировался Google Font Archivo
(вместе с Manrope для текста). При сборке (`next build`) TypeScript упал:
`next/font/google` для Archivo в этой версии Next.js не типизирует
`subsets: ["cyrillic"]` — сабсет недоступен. Заменил на единый шрифт Manrope
(вес до 800) для заголовков и текста.

**Причина:** сайт на русском языке, кириллица обязательна; Archivo без
кириллического сабсета непригоден.

**НЕ МЕНЯТЬ потому что:** если захочется другой шрифт для заголовков —
сначала проверить `subsets` для кириллицы в `node_modules/next/dist/...`
или на fonts.google.com, а не полагаться на память о шрифте из обучающих
данных (Next.js 16 в этом проекте — см. `AGENTS.md`, breaking changes
возможны).

из `layout.tsx` и все страницы схлопнутся в один canonical (обнаружено и
исправлено для дублирующихся `<title>` в процессе — см. следующую запись).

### Дубли в `<title>` из-за шаблона layout (2026-08-16)

**Решение:** `layout.tsx` задаёт `title.template: "%s — Zorin Fashion"`.
Часть новых страниц (страницы товаров, `/o-fabrike`) указывали в своём
`title` уже готовую строку вида `"... — Zorin Fashion, Бишкек"` — Next
подставлял её в шаблон и получалось `"... — Zorin Fashion, Бишкек — Zorin
Fashion"`. Убрал суффикс `"Zorin Fashion"` из title отдельных страниц,
оставив его только в шаблоне layout.

**НЕ МЕНЯТЬ потому что:** при добавлении новой страницы с `metadata.title`
— НЕ включать «Zorin Fashion» в конец строки, шаблон добавит сам.

### Editorial-редизайн через Skill ui-ux-pro-max (2026-08-16)

**Решение:** После сборки мультистраничного сайта пользователь дал фидбэк
«дизайн всё ещё очень нейронный и шаблонный, нужно разнообразие» и прислал
два репозитория — `ui-ux-pro-max-skill` (npm-скилл с дизайн-интеллектом,
офлайн Python) и `magic-mcp`/21st.dev (нужен API-ключ, отложили). Поставил
`ui-ux-pro-max` **локально в проект** через `npx ui-ux-pro-max-cli init
--ai claude` — глобальный `npm install -g` упёрся в EACCES permissions,
sudo не использовал.

Прогон `--design-system` с общим запросом («b2b manufacturer factory
industrial service») выдал generic B2B SaaS-палитру (тёмно-синий + Plus
Jakarta Sans, паттерн «Trust & Authority») — не подошло тематически для
швейной фабрики. Точечные `--domain style`/`--domain typography` запросы
(«editorial luxury heritage», «editorial elegant serif fashion») дали
куда более релевантный результат: стиль `editorial-grid-magazine`
(асимметричная сетка, pull-quote, drop cap, print-inspired typography) и
шрифтовую пару в духе Playfair Display + гуманистический sans.

Реальная причина «шаблонности» оказалась не в цвете/шрифте, а в том, что
5+ страниц использовали буквально один и тот же паттерн «фото + тёмный
градиент + заголовок снизу слева» для hero, и один и тот же
`rounded-2xl border bg-background-panel` card-grid для любого списка
преимуществ/фич. Правки:
- Добавлен `--font-serif` (Playfair Display, проверен на кириллицу) для
  всех крупных заголовков; `.font-display` (Manrope bold) остался для
  UI-элементов и подзаголовков — сознательная пара serif/sans, не замена.
- Hero на главной: убран паттерн «фото на весь экран + текст внизу слева»,
  сделана асимметричная композиция (текст слева с вертикальной линией,
  serif+italic заголовок, сплошная фотография только в верхней части).
- `/opt`: hero стал светлым сплит-макетом (текст + фото сбоку), список
  преимуществ — нумерованный список с serif-цифрами вместо card-grid.
- `/proizvodstvo-dlya-rf`: hero стал тёмным pull-quote-блоком без фото
  (текстовое высказывание про ЕАЭС), список причин — типографический
  список без карточек, с фото сбоку.
- Статьи блога (`src/lib/articles.ts`, `blog/[slug]/page.tsx`): добавлен
  новый тип блока `quote` (pull-quote с левой границей и курсивным serif),
  drop cap на первый абзац через CSS `.drop-cap` (`::first-letter`).

**Причина:** прямой фидбэк пользователя про «нейронность» + инструмент
подтвердил конкретный источник проблемы (повторяющиеся паттерны
компонентов, не палитра).

**НЕ МЕНЯТЬ потому что:** если добавлять новую страницу с hero-блоком —
NOT копировать один и тот же «фото+градиент+текст снизу» на все подряд.
Сейчас в проекте три разных hero-паттерна (фото-асимметричный на главной,
светлый сплит на `/opt`, тёмный pull-quote на `/proizvodstvo-dlya-rf`,
фото-баннер на страницах товаров) — осознанно разные, это и есть
исправление «шаблонности». Новый скилл лежит в `.claude/skills/` этого
проекта (не глобально) — при генерации дизайн-системы через
`--design-system` с общим B2B-запросом ожидать generic SaaS-результат,
для нишевых продуктов (мода, heritage-бренды) сразу идти в точечные
`--domain style`/`--domain typography` запросы.
