# ZORIN — старт для агента

**Дата:** 2026-08-17 · **Сессия:** 3

## Что это

Мультистраничный SEO-сайт швейной фабрики **ZORIN** (зарегистрированная
торговая марка; рабочее маркетинговое название сайта — «Zorin Fashion»,
см. раздел «Открытые вопросы»). Мужская классика: костюмы, пиджаки, брюки,
**жилеты** (да, шьют — см. историю решения в `PROGRESS_LOG.md`, сессия 2
ошибочно их убирала). Производство — с. Новопавловка, пригород Бишкека.
Фокус — опт/B2B от 500 единиц на модель, работа с российскими брендами,
оптовыми компаниями и корпоративными заказчиками (банки, отели,
авиакомпании — тендеры). Индивидуального пошива на частных клиентов сайт
не предлагает.

Домен `zorin-fashion.com` существует (заглушка «в разработке»). Сайт ещё
нигде не задеплоен — есть только локально.

## Логотип — теперь настоящий вектор

Пользователь прислал растровый логотип (`ZORIN` + галстук вместо буквы I,
тёмно-синий на белом). Он был **оттрассирован в точный SVG** через OpenCV
(`cv2.findContours` + `cv2.approxPolyDP`, evenodd fill-rule для дырок
О/Р) — не нарисован вручную, а именно повторяет контуры присланного файла
пиксель-в-пиксель. Скрипт трассировки нигде не сохранён (одноразовый, в
scratchpad сессии) — если понадобится перетрассировать другой файл, тот же
подход: threshold → `cv2.findContours(RETR_CCOMP)` → `approxPolyDP` →
SVG path с `fill-rule="evenodd"`.

- `src/components/Logo.tsx` — React-компонент, `fill="currentColor"`,
  используется в `Header.tsx` и `Footer.tsx` (наследует цвет текста —
  тёмный на светлом хедере, светлый на тёмном футере)
- `public/logo/zorin-logo.svg` — статичная версия с цветом `#1B2A3A`
- `~/Desktop/Zorin - логотип (вектор).svg` — тот же файл, копия для
  передачи клиенту/дизайнеру (закрывает блокер из брифа: «логотип нужен в
  векторе .ai/.svg/.eps/.pdf»)

## Стек

- Next.js 16 (App Router, Turbopack), React 19, TypeScript
- Tailwind CSS v4 (токены в `src/app/globals.css`)
- Шрифты: **Manrope** (`--font-body`) + **Playfair Display** (`--font-serif`,
  есть italic) — оба с кириллицей. Archivo не взлетел в сессии 1 (нет
  кириллического сабсета в `next/font/google`) — при новом шрифте всегда
  проверять `subsets` заранее
- `next/image` для всех фото (`public/images/`, `fill` + `sizes`)
- Без бэкенда/БД — чистая статика

- `src/lib/site.ts` — **главный источник фактов**: контакты, юр. лицо
  (`legalName`, `inn`), `stats` (foundedYear/employees/areaSqm/annualOutput),
  `whatsapp`/`telegram`/`contactPerson`. `email: null` — намеренно, см. ниже
- `src/lib/products.ts` — 4 линии продукции, у каждой `specs[]` (MOQ/срок/цена)
  для таблицы на странице товара
- `src/lib/faq.ts` — `faqItems`, 14 реальных вопросов из брифа (было 5
  общих placeholder-вопросов в сессии 1-2)
- `src/lib/articles.ts` — блог, `Article` теперь требует `image`/`imageAlt`
  (для сетки на `/blog`); `ArticleBlock` = `p | h2 | list | quote`
- `src/lib/nav.ts` — меню + `productLines` (для футера/навигации, 4 записи)
- `src/components/Logo.tsx` — см. выше
- `src/components/ProductPageContent.tsx` — общий шаблон для 4 товарных
  страниц, включая таблицу `specs`
- `src/app/layout.tsx` — JSON-LD `LocalBusiness` собирается из `site.ts`
  (`email` подставляется условно, только если не `null`)

Пользователь явно попросил (сессия 4) оставить на сайте видимые места под

везде ниже, при добавлении нового такого блока использовать его же, не
изобретать новый стиль.

- **Логотипы клиентов** (не путать с логотипом самого ZORIN — он готов, см.
  выше) — `/o-fabrike`, секция «Репутация», 4 плейсхолдера (Сударь, Stenser,
  Magman, Стрекоза). Плюс тонкая полоса `src/components/ClientLogos.tsx` на
  главной сразу под Hero (текстовые заглушки тех же 4 имён).
- **Реальные фото/видео цеха** — `/o-fabrike`, секция «Производство в
  кадре» (2 фото + 1 видео-плейсхолдер), сразу после «Оборудование и
  системы». Это отдельно от существующих 7 Unsplash-фото по сайту (те —
  декоративные заглушки хедеров, тоже ждут замены, см. ниже).
- **Кейсы с цифрами** — `/o-fabrike`, секция «Кейсы с цифрами», 2 плейсхолдера.
- **Отзывы** — `/o-fabrike`, секция «Отзывы», 3 плейсхолдера.
- **Награды/сертификаты (сканы)** — `/o-fabrike`, секция «Награды и
  сертификаты», 3 плейсхолдера.
- **Цена «от X»** — отдельного плейсхолдера не заводили: поле `specs[].value`
  с `label: "Цена"` в `src/lib/products.ts` (4 карточки товаров) уже сейчас
  хранит `"по запросу — под модель"` именно потому, что цифр нет ни в сайте,

  эту строку на `"от X сом/шт"` в каждой из 4 записей, разбираться больше
  ничего не нужно.

Если материалы придут — заменить конкретный `ContentPlaceholder` на реальный
контент (фото через `next/image`, текст отзыва и т.д.), не оставлять
плейсхолдер рядом с реальным.

## Открытые вопросы (не выдумывать ответ — спросить/сверить с клиентом)

- **Email не работает.** В брифе прямо написано: «будет зарегистрирован
  отдельно — нужен корпоративный адрес на домене». `site.email = null`,
  на сайте email нигде не показывается (заменено на WhatsApp/Telegram).
  Как только появится реальный адрес — вписать в `site.ts` и вернуть в
  `Contacts.tsx`/`Footer.tsx`.
- **«Zorin Fashion» vs «ZORIN».** В брифе зарегистрированная торговая
  марка — «ZORIN». Сайт по-прежнему использует «Zorin Fashion» как
  рабочее название в текстах/title (домен тоже zorin-fashion.com) —
  логотип при этом уже показывает именно «ZORIN». Решить с клиентом,
  нужно ли менять текстовое название сайта полностью на «ZORIN».
- **Расхождения внутри самого брифа** (не мои, документ сам себе
  противоречит) — уточнить у фабрики:
  - Сотрудников: карточка компании says 160, где-то рядом в тексте
    мелькает 156. На сайте используется 160.
  - Клиенты для упоминания: раздел 11 брифа называет их «согласованными
    к публикации» как «Сударь, Stenser, Magman, Стрекоза» — эти и
    использованы на сайте (`/o-fabrike`). В Части III (блокеры) тот же
    список внезапно даёт другие названия — «Stenser, Blackford, Tetro,
    Magman». Не добавлять Blackford/Tetro без подтверждения.
- **Вторая линия — мальчики/школьная форма.** Пользователь подтвердил
  (сессия 2/3), что это реальное и уже работающее направление, но
  **осознанно отложено** — сессия 3 занималась только насыщением
  существующей мужской линии реальными данными. Если возвращаться к этому
  — в брифе (Часть II, п.1) подробно расписано, как это структурировать
  (отдельный равноправный каталог, размеры 26–44, рост 110–182, не
  называть весь раздел просто «школьной формой»).
- **Вакансии.** В сессии 1-2 на сайте было упоминание про открытые
  вакансии швей/конструкторов — это было придумано, в брифе такого нет.
  Убрано из текстов в сессии 3. Не возвращать без подтверждения.
